# 07 — SysML v2 Emission Specification

**Status:** Baseline · **Decision:** ADR-001 · **Module:** `src/spec_forge/emit/sysml/`
**Implements:** SF-MIN-03, PRD output layer 2 (*"SysML v2 textual is a must"*)

---

## 1. Contract

```
emit_sysml(ir: SFIR) -> SysMLArtifact   # .sysml text + element↔IR id map
```

- **Deterministic.** Jinja2 templates over a validated IR. **No LLM call occurs in this module.**
- **Total.** Every valid IR emits. A gap is an upstream defect, never a template workaround (IR rule R2).
- **Stable.** Same IR → byte-identical output. Collections pre-sorted by id; no timestamps in model content.

The no-LLM rule is the concrete form of the PRD's own recommendation (*extraction into a schema followed by
deterministic code generation … is usually more reliable and easier to defend*) and it is what we will say in
the individual probes when asked why the SysML and the Modelica cannot disagree.

## 2. Output layout

One package per model, sectioned in a fixed order so diffs between runs are readable:

```
package TwoTankController {
    doc /* generated by SpecForge <version> from <run_id>. Do not hand-edit. */

    // 1. imports
    // 2. attribute definitions (quantities and units)
    // 3. port definitions
    // 4. interface definitions
    // 5. part definitions            (from archetypes)
    // 6. item definitions            (flowing media)
    // 7. part usages and nesting     (the system tree)
    // 8. connections
    // 9. state definitions           (behaviour)
    // 10. constraint definitions     (interlocks, limits)
    // 11. requirement definitions and satisfy relations
    // 12. verification cases
    // 13. rationale / assumptions as documentation comments
}
```

## 3. Mapping rules

| IR entity | SysML v2 construct |
|---|---|
| `Part` (archetype) | `part def <ArchetypeName>` — emitted **once**, reused by all instances |
| `Part` (instance) | `part <name> : <ArchetypeName>` nested under its parent |
| `Port` | `port def <PortTypeName>` + `port <name> : <PortTypeName>` |
| `Port.port_type` | Flow property direction: physical → `inout` flow pairs; signal → `in`/`out` |
| `Connection` | `connect <source> to <target>` inside the owning part, or an `interface` usage when typed |
| `Attribute` | `attribute <name> : <QuantityType> = <value>[<unit>]` |
| `StateMachine` | `state def <Name>` with nested `state`, `entry`, `exit`, `transition` |
| `Transition` | `transition first <src> accept <trigger> if <guard> then <tgt>` |
| `Constraint` | `constraint def` + `assert constraint` |
| `Requirement` | `requirement def <Id>` with `doc`, `subject`, `require constraint` |
| `Requirement.satisfied_by` | `satisfy <ReqId> by <element>` |
| `Assumption` | `doc` comment on the affected element **and** an `assume constraint` where expressible |
| `Conflict` | `doc` comment recording all positions and the rule applied |

### 3.1 Units and quantities

Units are emitted from the ISQ/SI library rather than as bare numbers:

```sysml
import ISQ::*;
import SI::*;

attribute T1_High : LengthValue = 0.80 [m];
```

Enforced by `V-UNIT-003`: no attribute may emit a bare numeric literal unless it is marked `dimensionless`.
Unit loss is the defect L2 and L3 are built to punish (ppm vs kg/kg vs normalised 1.0; RMS vs peak phasor), and
a SysML model that drops units is exactly the *"SysML that parsed but did not mean anything"* the briefing names
as a near-zero outcome.

### 3.2 Ports and causality

Physical ports emit conjugate flow/effort pairs; signal ports are directed.

```sysml
port def FluidPort {
    attribute pressure    : PressureValue;
    out item flow massFlow : MassFlowRateValue;
}
port def LevelSignal { out attribute level : LengthValue; }
```

`direction: acausal` on physical ports (IR §4.2) carries through here. Emitting a fluid port as directed would
produce SysML that parses and misrepresents the physics.

### 3.3 State machines

L1's controller, with the semantics the design review fixed:

```sysml
state def TankControllerStates {
    entry; then IDLE;

    state IDLE;
    state FILL_T1 {
        entry action cmdV1Open;
        exit  action cmdV1Close;
    }
    state WAIT_AFTER_FILL;
    state SHUTDOWN;

    transition idle_to_fill
        first IDLE
        accept START
        then FILL_T1;

    transition fill_to_wait
        first FILL_T1
        accept when tank1.level >= T1_High
        then WAIT_AFTER_FILL;

    transition any_to_shutdown
        first *                       // highest priority: SHUT > STOP > START
        accept SHUT
        then SHUTDOWN;
}
```

Transition **priority** and timer **suspend semantics** (`freeze_remaining`) have no first-class SysML v2
textual syntax. They are emitted as `doc` comments on the transition **and** carried losslessly in the IR, from
which the Modelica emitter generates the real behaviour. Recorded here explicitly so the limitation is a stated
design position rather than a silent gap — and so anyone answering an individual probe on it gives the same
answer.

### 3.4 Requirements and traceability

```sysml
requirement def <'URS-F-003'> {
    doc /* V1 shall close when Tank 1 reaches the specified high-level limit.
           Source: URS-001 Rev A, p.1 §3  (fragment frag:urs001#p1.s3.r4) */
    subject controller : TankController;
    require constraint { tank1.level >= T1_High implies not cmdV1 }
}

satisfy <'URS-F-003'> by controller.states.FILL_T1;
```

Every requirement carries its source fragment id in `doc`. This is what makes the SysML artifact independently
traceable when read outside our UI — a judge opening `model.sysml` in a text editor can follow any element back
to the document that justified it, without running anything.

### 3.5 Assumptions and conflicts as documentation

```sysml
part tank1 : Tank {
    doc /* ASSUMPTION assume:tank_1_outlet (SA-FLUID-002, confidence 0.95):
           Tank TK-101 has a liquid outlet port. No document states it; implied by IF-HYD-03. */
    doc /* CONFLICT conflict:t1_high — resolved PRE-01-tier.
           Selected 0.80 m (CR-004, tier 1, 2026-03-11).
           Rejected 0.78 m (URS-001 Rev A, tier 3, superseded) and 0.78 m (legacy .mo, tier 11). */
    attribute highLimit : LengthValue = 0.80 [m];
}
```

## 4. Validation

`toolchain/sysml.py` invokes the SysML v2 pilot toolchain on every emission.

| Gate | Severity | Effect |
|---|---|---|
| Parses without syntax error | **error** | Blocking — emission is a defect if it does not parse |
| Name resolution succeeds | **error** | Blocking |
| No unresolved imports | error | Blocking |
| All IR elements present in output | error | Blocking — checked by the element map, not by eye |
| Style/lint | info | Reported |

The element-map check closes the loop that makes the artifact trustworthy: emission records an
`ir_id → sysml_qualified_name` map, and the validator asserts the map is **total** over emittable IR entities.
A part that silently vanished from the template is caught mechanically rather than at the review.

## 5. Round-trip consistency

The element map is the input to the SysML↔Modelica consistency checker
(`09_validation_and_repair_spec.md` §6), which asserts that the set of parts, ports and connections in the
emitted SysML matches the set in the emitted Modelica, element for element. This is the explicit answer to the
PRD's warning about silent divergence and is one of the named stretch-bonus items (*"a traceable SysML→Modelica
transformation"*).
